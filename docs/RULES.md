# Probe Rules v1 合同

本文档定义运行时实际执行的语义约束。JSON Schema 适合编辑器和通用校验器，但无法完整表达指纹长度公式、哈希区分度和跨规则冲突，因此不能替代本文档及 SDK 解析器。

## 文档边界

- 编码必须是严格 UTF-8，可以带 UTF-8 BOM。
- 文件非空且不得超过 4 MiB，以原始字节数计算。
- JSON 必须使用标准严格语法；拒绝重复字段、未知字段、尾随内容、注释和宽松数字。
- 所有整数必须是普通十进制整数，不接受 `1.0`、`1e3` 或字符串形式。
- 根节点固定包含 `format`、`schemaVersion`、`revision`、`algorithm` 和 `rules` 五个字段。

## 固定算法

`algorithm` 固定为 `spectral-sequence-v1`，参数不在规则文件中重复保存：

| 参数 | 固定值 |
| --- | ---: |
| PCM 采样率 | 16000 Hz |
| 分析窗口 | 512 ms |
| 窗口步长 | 256 ms |
| 频带数量 | 16 |
| 最少确认帧 | 4 |
| 最多确认帧 | 8 |

改变任一算法参数必须使用新的 `algorithm` 标识或新的 schema 版本，不能静默复用 v1。

## 根节点

| 字段 | 约束 |
| --- | --- |
| `format` | 固定为 `ad-audio-probe-rules` |
| `schemaVersion` | 固定为整数 `1` |
| `revision` | `1..9007199254740991`；同一规则 URL 的内容变化必须递增 |
| `algorithm` | 固定为 `spectral-sequence-v1` |
| `rules` | 数组，最多 1024 条；空数组合法 |

Probe 只接受更高 revision。同 revision 的原始文件摘要不同会被视为发布冲突，较低 revision 会被拒绝；已有的可信缓存继续生效。

## 单条规则

| 字段 | 约束 |
| --- | --- |
| `id` | 全局唯一；匹配 `^[a-z0-9][a-z0-9._-]{0,63}$` |
| `durationMs` | `1000..600000` |
| `anchorOffsetMs` | 非负整数 |
| `anchorDurationMs` | `2000..5000` |
| `fingerprints` | 恰好四个固定相位，见下一节 |
| `test` | 可选的采集器测试元数据；Probe 校验后忽略 |

锚点必须完整位于广告区间内：

```text
anchorOffsetMs + anchorDurationMs <= durationMs
```

规则只要存在于 `rules` 数组中就会参与匹配。v1 没有启用、待验证或优先级字段。

`test` 对象只允许以下两个必填字段：

| 字段 | 约束 |
| --- | --- |
| `url` | `http` 或 `https` URL，长度不超过 8192 个字符 |
| `adStartMs` | `0..9007199254740991`，且加上 `durationMs` 后仍在安全整数范围内 |

测试终点不重复保存，由 `adStartMs + durationMs` 推导。测试元数据改变同样属于规则文件内容变化，发布时必须递增 revision。

## 指纹相位

`fingerprints` 必须恰好包含 `phaseMs` 为 `0`、`64`、`128`、`192` 的四个对象，每个相位只能出现一次。`hashes` 中每项是八位小写十六进制字符串。

每个相位的哈希数量必须严格等于：

```text
floor((anchorDurationMs - phaseMs - 512) / 256) + 1
```

单个序列解析上限为 64，整个文件的哈希总数上限为 65536。当前锚点时长范围下实际序列更短，但解析上限仍用于拒绝异常输入。

每个相位在前八帧内必须至少出现一帧与首帧的 Hamming 距离大于 5，否则规则会因开头区分度不足被拒绝。这样可以把确认帧数限制在 4 到 8 帧内。

## 跨规则冲突

零相位主指纹以前八帧或完整较短序列作为前缀。两个规则的主指纹存在相同或包含关系时，它们必须推导出相同的广告结束偏移：

```text
durationMs - anchorOffsetMs
```

否则两条规则会在运行时产生不可安全裁决的跳转目标，整个规则文件会被拒绝。静态校验只是第一道门：运行时会把归一化检测时刻相近或广告区间严格重叠的证据视为潜在同一广告，并对跨 occurrence、跨 PCM 批次和链式重叠持续消歧。任意相关证据的结束位置跨度超过 250 ms 时，相关区间全部 fail-open，不派发跳转；首尾严格相邻且证据时刻独立的广告不受影响。

## 发布建议

- 先由 SDK 解析器完成严格校验，再发布到规则 URL。
- 内容、测试元数据或规则顺序有变化时都递增 revision。
- 使用原子替换发布文件，避免客户端下载到截断 JSON。
- 保留上一版可回滚文件，但回滚时必须发布更高 revision，不能复用先前 revision。
